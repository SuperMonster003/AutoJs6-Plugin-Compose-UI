# v1.6.0

###### 2026/10/15

* `提示` 設計器新增 UI (XML) 專案: 可以開啟與編輯傳統 "ui" 模式指令碼 (E4X XML 佈局), 畫布由 AutoJs6 繪製. 佈局預覽需要包含預覽服務的 AutoJs6 6.8.0 建置 (宿主提交 306a8f7834 之後), Android 11 (API 30) 起畫布嵌入 AutoJs6 繪製的真實檢視, 更舊版本顯示點陣圖快照; 沒有該服務時仍可編輯, 畫布說明原因
* `新增` 設計器支援 UI (XML) 專案: 新建專案時可選 "UI (XML)", 匯入或從 AutoJs6 編輯器 / 檔案管理器開啟 "ui" 模式指令碼也按 UI 專案讀取; 首頁清單以 JS / TSX / UI 標註專案類型. 指令碼中的 XML 佈局以帶位置的語法樹保存, 未觸碰的部分 (空白, 註解, 屬性順序, 引號, {運算式}) 逐位元組保留, 只有被編輯的開始標籤, 文字與新插入的元素會被改寫; 指令碼裡的其他 XML 字面值也能切換到畫布編輯
* `新增` UI 專案的編輯頁: 大綱 (摺疊, 上下移, 刪除, 長按拖曳, 多個佈局時切換), 屬性抽屜 (標籤, id, 文字內容, 已設定的屬性與按 View 類別分組的目錄屬性, 文字 / `{{ }}` 繫結 / {運算式} 三態, 裸屬性, 任意屬性名稱), 元件面板 (文件的 48 個標籤, 按分類列出並帶預設屬性), 繫結值面板 (`{{ }}` 名稱的求值結果與暫時覆寫, 只影響畫布), 問題清單 (按文件站的標籤與屬性目錄檢驗) 與主控台 (AutoJs6 繪製佈局時回報的診斷); 儲存, 草稿復原, 來源同步, 傳送執行, 在 AutoJs6 編輯器中開啟, 匯入 AutoJs6 指令碼目錄, 複製與匯出對 UI 專案同樣可用
* `新增` UI 專案的畫布由 AutoJs6 繪製 (佈局預覽): 外掛把 XML 片段與繫結值交給 AutoJs6 的預覽服務, AutoJs6 用 ui 模式的佈局器建立真實檢視並畫回畫布, 不執行專案的指令碼; 點選與拖曳在畫布上照常運作, 繪製失敗時定位到出錯的元素; 預覽執行階段以 "3-Block Compose 預覽" 出現在 AutoJs6 的執行清單中, 可從那裡停止
* `新增` UI 專案的屬性抽屜可以為選取的元素新增事件: 在 ui.layout 呼叫之後附加一段 `ui.<id>.on('事件', ...)` 處理函式樣板 (元素沒有 id 時自動補一個), 處理邏輯在指令碼編輯器中編寫; 指令碼已註冊的事件顯示為 "指令碼中已處理"
* `相依` 附加 ui-preview-api.aar 契約製品 (AutoJs6 ui 佈局預覽契約 v1), 供設計器請求 AutoJs6 繪製 UI 專案的畫布

# v1.5.0

###### 2026/10/14

* `提示` 設計器的互動預覽現在會執行 JavaScript 專案的指令碼 (需要 Android 8.0 或更新版本). 指令碼在外掛內受限的沙盒中執行: 只能使用 compose, console, toast 與計時器, 不能存取 Java / Android 或其他 AutoJs6 模組, 執行結果只顯示在畫布上, 不會修改專案. TSX 專案與 Android 8.0 以下的裝置沿用之前的互動預覽
* `新增` 互動預覽執行指令碼: 開啟 "互動預覽" 後, JavaScript 專案的轉譯函式與事件處理函式真實執行, 點擊按鈕, 輸入文字, 撥動開關等會按指令碼的邏輯更新畫布; 狀態面板中的預覽值作為 state 的初值, 修改專案或預覽值後指令碼自動重新執行
* `新增` 新增 "主控台" 頁: 顯示預覽中指令碼的 console / log 輸出, toast 與錯誤; 指令碼出錯時畫布底部顯示錯誤, 點擊可開啟主控台; 單次執行超過約 3 秒 (例如無限迴圈) 時預覽會停止指令碼並說明原因, 設計器本身不會卡住
* `新增` 指令碼執行時, "互動預覽" 開關上顯示執行圖示
* `修正` 編輯模式下, 畫布中的輸入框有時會自動取得焦點並彈出鍵盤 (多見於 Android 7.x), 遮住下方的面板; 現在編輯模式下畫布中的元件不會取得焦點, 退出互動預覽時也會收起鍵盤

# v1.4.0

###### 2026/10/13

* `提示` 設計器的 TSX 專案需要 TypeScript Engine 0.7.0 或更新版本; 未安裝或版本過舊時, TSX 專案只能以唯讀原始碼方式檢視與複製
* `新增` 設計器支援 TSX 專案: 新增專案時可選 JavaScript 或 TSX, 也可以匯入 .tsx 檔案, 或從 AutoJs6 編輯器與檔案管理員直接開啟 .tsx 檔案; TSX 原始碼由 TypeScript Engine 解析後在畫布中編輯, 儲存為統一格式的 TSX (4 空格縮排, 單引號屬性, 每個子元素一行); 設計器無法編輯的寫法 (例如別名標籤, 條件或迴圈產生的子元素) 按原文保留, XML 標籤與展開屬性等無法表示的寫法會拒絕開啟並指出行列
* `新增` 設計器中 TSX 專案的 "執行" 會把專案檔案交給 AutoJs6, 由 TypeScript Engine 編譯後執行; 有未儲存的修改時先儲存
* `新增` TypeScript Engine 未安裝, 版本過舊或解析服務暫時無法使用時, 設計器以唯讀方式顯示 TSX 專案的原始碼並說明原因, 可以複製原始碼或重試; 安裝或更新 TypeScript Engine 後回到設計器會自動重試
* `修正` 設計器儲存無法寫回的外部指令碼時, 檔名含空格, 括號等專案名稱不允許的字元會使外掛閃退, 而不是另存為專案的問題; 現在這些字元換成 "-" 後另存, 匯入指令碼也按同一規則命名
* `最佳化` TSX 專案中編輯事件處理函式時由 TypeScript Engine 檢查語法, 可以使用型別標註等 TypeScript 寫法
* `相依` 附加 typescript-parser-api.aar 契約製品 (TypeScript 語法樹解析契約 v1), 供設計器讀取 TSX 專案

# v1.3.0

###### 2026/10/13

* `新增` 設計器中經 "匯入指令碼" 得到的專案可在編輯頁選單中 "寫回來源" 或 "從來源重新匯入": 匯入時保留對來源檔案的存取權限 (檔案提供者允許時), 來源或專案在上次同步後被修改過時先詢問, 來源檔案無法開啟時可重新選擇以恢復關聯; 儲存專案不會自動寫回來源
* `新增` 設計器畫布可預覽 Image 的圖片: '@drawable/名稱' 取自已安裝的 AutoJs6, 相對路徑在編輯頁選單 "圖片資料夾" 選定的資料夾中尋找 (僅保留唯讀存取權限); 網址與絕對路徑仍顯示佔位, 原因列在問題清單中
* `新增` 設計器編輯頁新增 "狀態" 面板: 列出指令碼頂層的 compose.state 與其初值, 可以暫時修改預覽值, 只影響畫布, 不寫入指令碼也不產生復原步驟; 開啟畫布右上角的 "互動預覽" 後可以直接操作畫布中的元件, 繫結了狀態的開關, 滑桿, 輸入框, 選擇項, 分頁等控制項會修改對應的預覽值 (指令碼中的事件處理函式不會執行), 關閉後恢復點選與拖曳
* `修正` 介面中某個容器前部的子節點被插入, 刪除或移到別處時, 其後的子節點會被整體重建, 遺失它們自己的狀態 (例如 LazyColumn 的捲動位置) 的問題; 現在這些子節點保持原有狀態, 也不再重複建構
* `修正` 設計器屬性抽屜修改輸入框 (TextField / OutlinedTextField) 的 text 後, 畫布中的輸入框仍顯示舊文字的問題
* `最佳化` 設計器畫布中長按拖曳節點時, 會依目標容器的排列方向 (縱向, 橫向, 網格) 顯示插入線, 放開後節點放到指標所在的位置, 不再只能附加到容器末尾
* `最佳化` 設計器畫布中的 AndroidView 改為依其尺寸修飾 (如 h, fillMaxWidth) 顯示淺色佔位區域, 並在其中顯示 view 運算式的原始碼
* `最佳化` 設計器屬性抽屜中的修飾鏈可以按住每項左側的把手拖曳排序, 放開前顯示插入線; 上移 / 下移按鈕仍然保留
* `最佳化` 設計器畫布中開啟狀態 (open 為 true) 的彈出層元件改為按接近真實的樣式畫在畫布的邏輯螢幕內: AlertDialog 與 ModalBottomSheet 連同遮罩蓋在頁面上方, DropdownMenu 與 Tooltip 顯示在錨點下方或上方, 點選彈出層中的節點即可編輯; 不再以卡片形式插在頁面中, 也不會彈出真實視窗
* `最佳化` 設計器畫布在每次編輯後只重新組合發生變化的節點, 並減少記錄節點位置的開銷, 較大的文件 (約 250 個節點) 復原 / 重做後的畫面重新整理明顯更快
